Dilarang menampilkan foto atau ilustrasi wajah/manusia pada placeholder: gunakan area kosong berwarna hijau/putih hangat, ikon daun atau ikon foto. Mobile-first 390px, wajib aman pada 320px, tablet 768px, desktop 1440px tanpa horizontal scroll. Nama lengkap panjang harus wrap dengan alami tanpa clipping. Target sentuh minimal 44px, jarak antartombol jelas, safe-area untuk kontrol mengambang. Komposisi lapang; setiap bagian memiliki fokus visual. Semua label, pesan kesalahan, dan CTA dalam Bahasa Indonesia.

Perilaku: pembuka “Buka Undangan”; lagu baru diputar setelah interaksi pengguna dan hanya jika sudah ada file lagu, kontrol “Putar musik”/“Jeda musik” selalu dapat ditemukan. Placeholder lagu tidak mengklaim audio sedang diputar. Scroll native dengan parallax multilayer: tree cutout di foreground setiap section, latar hutan lebih lambat, transisi kamera semu memasuki joglo dari cover ke isi. Fade-in isi 500–700ms; depth, perspective dan bayangan pada dekorasi, tidak ada scroll hijacking. Undangan tamu one page seamless tanpa menu navigasi. Hormati prefers-reduced-motion, tampilkan semua isi tanpa animasi jika diminta. Foto lazy-load, cover prioritas, peta dimuat saat mendekati bagian lokasi. Kontrol keyboard dan focus terlihat, foto meaningful punya alt text, ornamen aria-hidden.

Keamanan sebagai konteks desain: masing-masing tamu menerima tautan token acak yang unik, maksimal 3 perangkat terdaftar per tautan. Penghitungan wajib di backend berdasarkan identifikasi/fingerprint terverifikasi dan sesi; pengunjung ulang perangkat sama tidak memakai slot lagi. Tidak tampilkan token/fingerprint mentah. Tamu melihat hanya data dirinya. Tampilkan state memverifikasi, tautan tidak valid/dicabut, batas perangkat tercapai dan layanan gagal dengan coba lagi. Fingerprint tidak dapat menjamin identitas perangkat fisik 100%; beda browser/perubahan setting dapat dihitung baru, sehingga perlu pemulihan via admin.

CMS: login admin, ringkasan, kelola tamu (nama, tautan unik, status akses, perangkat), detail tamu dan pencabutan perangkat, pengaturan foto (cover dan galeri, alt text, urutan, hapus dengan konfirmasi), pengaturan satu lagu (unggah/ganti, preview play/pause, nama berkas, state belum ada lagu), pengaturan acara (nama pasangan, tanggal, jam, lokasi, tautan Maps dan URL embed), preview undangan mobile, simpan dengan feedback sukses/gagal dan peringatan perubahan belum disimpan. Tidak menambahkan analitik, pembayaran, hadiah digital atau fitur di luar kebutuhan.

Hosting target render.com. Ini konteks implementasi developer, jangan tampilkan nama hosting, fingerprint, kode, atau env vars di halaman tamu. Desain bukan bukti implementasi backend atau deployment.

## Prompt implementasi setelah desain dipilih

Bangun undangan dari desain Google Stitch yang telah diperiksa, jangan sekadar menayangkan HTML mockup. Ikuti revisi one page immersive di bagian Arah terbaru: tidak ada menu navigasi di undangan tamu, cover masuk joglo via parallax dan foreground pohon beranimasi pada setiap section. Terapkan nama, tanggal, adat Solo, palet dan placeholder di atas. Buat alur tamu dan CMS bekerja end-to-end, animasi scroll aksesibel, serta layout 320/390/768/1440px. Tautan unik harus token acak kriptografis; nama tamu diperoleh server, bukan parameter nama yang dapat diubah. Token disimpan dalam bentuk hash, disensor dari log dan tidak dikirim ke layanan pihak ketiga. Verifikasi sebelum mengirim isi privat. Penggunaan fingerprint dan sesi merupakan identifikasi browser terbaik yang tersedia, bukan bukti perangkat fisik yang sempurna. Jangan memakai hash sederhana dari user-agent/IP sebagai jaminan keamanan. Tentukan provider/metode fingerprint yang terverifikasi server sebelum implementasi; API key/server secret tidak boleh berada di frontend. Hitung pendaftaran perangkat dalam transaksi dengan batas 3, menangani permintaan serentak, dan cegah perangkat lama memakai slot baru saat membuka ulang. Jangan daftarkan perangkat ketika bot preview tautan hanya mengambil cover. Perangkat keempat ditolak; pencabutan perangkat membatalkan sesi dan melepas slot. Pencabutan tautan membatalkan semua sesi tautan tersebut. Pemulihan dilakukan admin dengan konfirmasi; pembatasan tidak boleh dapat dilewati dengan sekadar mengganti ID di client. Perlakukan token sebagai akses bearer yang dapat diteruskan, jangan menjanjikan penerima tidak dapat membagikan undangan.

Lindungi CMS dengan login admin, hash password yang sesuai, cookie sesi HttpOnly/Secure/SameSite, proteksi CSRF dan rate limit. Validasi input dan file pada server; nama/jenis file diperiksa, konten dan ukuran diverifikasi, tolak executable/SVG aktif, berikan nama penyimpanan acak. Semua perubahan tamu, foto, lagu dan acara harus persisten dan punya feedback sukses/gagal. Konten teks tamu harus di-escape. CMS hanya dapat diakses admin. Jangan masukkan kredensial ke repository atau contoh data. Jangan mengirim pesan undangan otomatis; admin menyalin tautan untuk dibagikan sendiri.

Sediakan pengaturan lokasi berisi nama tempat, tautan buka Maps dan URL embed terpisah. Shortlink maps.app.goo.gl bukan src iframe. Pakai URL embed resmi dari Google Maps Share > Embed a map bila tersedia, atau Maps Embed API place dengan API key dibatasi origin. Iframe diberi title, loading=lazy, dimensi minimal 200x200 dan referrerpolicy=strict-origin-when-cross-origin agar token URL tidak bocor. Jika URL embed belum tersedia, tampilkan fallback lokasi dan tombol Maps yang tetap berfungsi; jangan tampilkan peta palsu sebagai peta aktif.

Siapkan deployment render.com: web service bind ke 0.0.0.0 dan PORT dari lingkungan, health check, rahasia melalui environment, penyimpanan database persisten untuk tamu/sesi/pengaturan dan storage persisten untuk foto/lagu. Filesystem default Render bersifat ephemeral, sehingga upload tidak boleh hanya tersimpan di direktori runtime. Pilih persistent disk pada layanan yang mendukung atau object storage; jelaskan kebutuhan sebelum deployment. Sertakan konfigurasi Render yang cocok dengan stack yang benar-benar dipilih, panduan menjalankan lokal, seed placeholder yang tidak mengandung kredensial, serta migrasi database. Jangan mengklaim sudah live tanpa URL layanan dan pemeriksaan langsung.

Verifikasi alur: admin login; tambah/edit tamu; token unik; perangkat 1–3 masuk; buka ulang tidak menambah slot; perangkat 4 ditolak; pendaftaran serentak tetap maksimal 3; pencabutan sesi dan link; akses silang antar tamu ditolak; uploader valid/invalid dan persistence setelah restart; musik menunggu klik; foto placeholder; peta fallback/embed; save CMS gagal tidak membuang perubahan; scroll/reduced-motion; keyboard/focus; viewport kecil tanpa overflow. Jalankan pemeriksaan deployment nyata setelah layanan dibuat.
